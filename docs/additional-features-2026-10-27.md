# ERPS 추가 기능 구현과 검증

기준일: 2026-10-27 KST. [QA 검토 보고서](qa-review-2026-10-26.md)의 F-01~F-12를 기준으로, 기존 데이터로 구현 가능한 기능을 추가했다. 계정·영구 작업 큐·영상 원본이 필요한 기능은 아래에서 구현 범위를 구분한다. 기존 작업 중이던 개인 성적 등급과 분석 개선 코드는 보존했다.

## 저장·API·운영 변경

- 분석 캐시 버전은 **20**이며 전체/선택 픽을 캐시 조회와 저장 키에서 분리한다. 기존 캐시 JSON과 equipment JSON을 사용하므로 이번 기능을 위한 DB 마이그레이션은 없다. 이전 경기 상세를 복원하기 위한 운영 재수집은 실행하지 않았다.
- 추천의 `playerDataScope`가 개인 프로필 조회·수집·팀원 프로필·설명까지 전달된다. 현재 메타가 없는 후보의 순위를 0.00으로 표시하던 경로는 후보 생성을 보류한다.
- 조합 목록 읽기에는 60초 제한 크기 캐시와 안정적인 정렬을 추가하고, 조합 개수는 모든 행을 가져오는 대신 count 조회를 사용한다. 일반 성능 개선율이나 운영 p95는 측정하지 않았다.
- 집계 저장을 250행 배치로 나누고 `ingestion_runs`에 성공/실패와 구조화 진단을 기록한다. 프로세스 내부 중복 실행도 차단한다. 초기 DB 연결 실패 시 잠금이 해제되는 회귀 검사도 포함한다.
- **QA-005의 운영 장애가 해결됐다고 판정하지 않는다.** 원자적인 완료 집계 공개, 여러 프로세스 간 잠금, 체크포인트 재개와 실제 운영 규모의 재집계 검증이 남아 있다. 현재 DB에서도 실험체/조합 집계 시점 차이가 관측된다.
- 인증 설정이 없거나 예제값 `change-me`이면 관리자·수집 API는 503으로 차단한다. 유효한 설정의 올바른 토큰만 허용한다. 현재 로컬 ADMIN_TOKEN과 CRON_SECRET은 예제값이므로 실제 관리·수집 호출 전에 운영자가 유효한 값으로 설정해야 한다. 이번 작업에서 자격 증명을 변경하지 않았다.
- `ER_NEXT_DIST_DIR`로 별도 검증 빌드 경로를 선택할 수 있다. 기본은 기존 `.next`이며 이번에는 `.next-qa`에서 빌드·실행했다.

## 상위 API가 필요한 위치

이번에 구현한 탐색·통계·픽 선택·내보내기·운영 조회·근거 질문에는 신규 유료 API나 상위 AI 모델이 필요하지 않다.

| 위치 | 필요한 판단 |
| --- | --- |
| 팀원 닉네임 다중 조회와 처음 분석할 때의 전적 보강 | 실제 키 한도·호출 수·지연을 측정한 뒤 게임 API Production Key 검토. 먼저 프로필 캐시·증분 갱신·키 단위 공유 제한기 필요 |
| 세밀한 MMR 코호트 | 필요한 MMR 필드가 누락되는 경우 제공자의 해당 필드 접근 권한 확인. 현재 키 등급과 개별 권한은 미확인 |
| 서버 재시작 후 분석 재개·여러 인스턴스 동시 처리 | 영구 작업 저장소·워커·공유 요청 제한기 필요. AI 모델 등급을 올려 해결할 수 있는 부분이 아님 |
| 자유로운 후속 대화 | 실제 근거 이탈·수치 보존·비용·지연 평가 후 LLM 도입/상위 모델 검토. 현재 질문 기능은 외부 LLM을 호출하지 않음 |
| 영상·교전·이동 피드백 | 실제 원본 입력 또는 제공 API 확보가 선행 조건. 모델 변경만으로 누락된 원본을 확보할 수 없음 |

API별 상세 조사와 공식 출처는 [기존 검토 보고서](qa-review-2026-10-26.md)의 API 의존성 절을 참고한다. 키 변경·구매·배포는 실행하지 않았다.
