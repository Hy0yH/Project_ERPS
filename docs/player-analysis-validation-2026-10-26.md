# 플레이어 분석 수치 검증 및 개선

2026-10-26에 요청받은 **겜덕후, 하스, 음침해지기, 세시아, 사린**의 공식 전적을 조회해 저장 데이터 및 수정한 분석 결과와 대조했다. 시즌 41, 패치 12.6.0, 랭크 스쿼드만 사용했다. 최대 최근 50판을 분석하며 겜덕후·사린은 이전 패치까지 조회했을 때 현재 패치 기록이 각각 17·18판이었다.

35개 실제 지표, 14개 비교용 개인 수치, 분석 경기 수를 독립 계산식으로 대조한 **250개 항목이 일치**했다. 실제 비교군의 기준값·유효 경기 수·플레이어 수와 강점의 방향 검증까지 포함해 **432개 항목을 통과**했다. 전체 테스트와 타입 검사, 프로덕션 빌드도 확인했다. 브라우저에서는 실제 전적 재생 화면의 데스크톱·390px 모바일 표시와 펼침 패널·경기 목록을 점검했다.

산출값과 비교 범위는 [검증 결과 JSON](evidence/player-analysis-2026-10-26.json), 비밀값·외부 UID를 제거한 원본 표본과 고정 기대값은 [회귀 테스트 표본](../tests/fixtures/player-analysis-real-cases.json)에 있다.

## 발견한 문제와 변경

1. **사용 크레딧 매핑 오류**: 저장 기록과 겹치는 106건 중 104건에서 `total_spent_vf_credit`이 공식 `totalUseVFCredit`과 달랐다. 기존 코드는 이전 배열 필드만 합산했다. 현재 스칼라 필드를 우선하고 과거 배열 형식도 지원한다. 대조한 나머지 8개 저장 필드에서는 불일치가 없었다. 기존 DB의 모든 과거 행을 일괄 수정한 것은 아니며, 새 수집부터 올바르게 저장하고 플레이어 분석은 이번 공식 응답을 우선한다.
2. **공식 응답의 패치 일부 누락**: 185건 모두 `versionSeason`이 없었다. 순수 분석기에 그대로 넣으면 엄격한 패치 필터에서 모두 제외됐다. 서비스에서는 저장된 기록으로 일부 보완될 수 있으므로, 이를 기존 전체 분석이 항상 0판이었다는 의미로 해석하면 안 된다. 이제 독립적으로 확인한 시즌·정확한 major/minor·랭크 모드·패치 시작 시각이 모두 맞을 때만 빠진 시즌 버전을 보완한다. 알 수 없는 버전이나 이전 패치는 계속 제외한다.
3. **오래된 저장 값이 새 원본을 덮음**: 동일 경기에서는 방금 받은 공식 기록을 우선한다. 저장 전적 조회가 지연되어도 확보한 공식 전적으로 실제 수치를 계산한다. 최신 50판은 시간대 표기가 달라도 실제 시각으로 정렬한다.
4. **미수집과 0 혼동**: 수집한 숫자를 원본 메타데이터에 보존하고 미수집 필드와 실제 0을 구분한다. 지표별 유효 경기 수를 공개한다. 팀 킬이 0인 경기의 킬 관여율과 활동 시간이 없는 분당 지표는 분모가 없으므로 제외한다.
5. **RP·경기 시간의 의미 혼동**: 분당 지표에는 활동 시간 `playTime`만 쓴다. 관전·전체 시간은 별도 표시한다. 실제 RP는 유효한 전후 차이를 우선하고 전후 값이 없거나 0이면 공식 Gambit 포함 증감, 기본 증감 순으로 확인한다. 음침해지기의 경기 `66833900`은 시작 RP 7,970·종료 RP 0·공식 증감 0이어서 단순 차감하지 않는다. 해당 표본 평균 실제 RP는 +3.58이다.
6. **결과 점수 과장**: 플레이어별 평균 분포의 표준편차를 개인 경기 수의 제곱근으로 다시 나누던 방식을 제거했다. 승률·TOP3·순위·RP도 다른 지표처럼 플레이어별 집계값의 백분위와 기존 표본 신뢰도 보정을 사용한다. TOP3 기록과 행동 지표의 관계도 플레이어별·활동 시간 기준을 맞춰 계산한다.
7. **강점 문구의 모순**: 하스의 승률은 평균보다 낮으면서 백분위가 높은 분포 사례였다. 강점은 상대 점수 65 이상뿐 아니라 관측값도 표시된 기준보다 유리해야 한다. 점검 제안은 상대 점수 35 미만이며 실제 기준값보다 불리한 경우에만 만든다. 정상 성장이라는 맥락 설명도 실제 비교 방향을 확인한다.
8. **성장 속도 오해**: 종료 무기 숙련도를 경기 시간으로 나눈 값은 실제 시간대별 성장 속도가 아니다. 참고 수치로 남기고 성장 점수·강점·행동 제안에서 제외했다.
9. **비교군 조회 시간 초과**: 시즌 전체에 대한 큰 offset 조회를 없애고 현재 패치 경기 ID 범위 내에서 10,000 ID씩 나눈 뒤 `(game_id,user_num)`으로 이어 읽는다. 1,000행 페이지·최대 3개 독립 구간 동시 조회를 사용한다. 페이지·구간 경계의 누락 및 중복 회귀 테스트를 추가했다. 같은 209,969행 조회가 순차 500행 방식 190.1초에서 최종 방식 57.9초로 줄었다. 이는 개별 비교군 조회 측정이며 전체 분석 API의 응답 시간은 아니다. 조회 실패 시 일부 비교군으로 점수를 만들지 않고 실제 통계만 유지한다.

필드 의미는 [공식 Open API 문서](https://developer.eternalreturn.io/static/media/OpenAPI_EN_20260917_01.html)의 활동·관전 시간, 크레딧, RP 정의를 확인했다. 종료 RP 0의 처리는 관측된 이상값에 대한 방어 규칙이다.

이 표는 수집된 확장 후보군의 크기다. 실제 지표는 기본 구간/확장 구간, 같은 픽/역할군/전체, 지표별 결측과 플레이어별 최소 경기 조건을 적용하므로 각 지표의 최종 표본 수는 다르다. 상세 값은 검증 JSON에 남겼다. 중첩되는 MMR 구간이므로 행 수를 합쳐 고유 경기 수로 해석하면 안 된다.

실제 수치와 집계의 일치는 검증했지만, 상대 점수가 미래 랭크 상승을 예측하는 정확도나 제안의 인과 효과를 검증한 것은 아니다. 저장된 비교군은 프로젝트가 수집한 전적이며 전체 랭크 플레이어의 무작위 표본이 아니다. 표본이 부족한 전투 평가를 강제로 표시하지 않는다. 과거에 원본이 저장되지 않은 추가 필드는 새 수집 전까지 미수집일 수 있다.

## 재현

자격 증명이나 네트워크 없이 고정 표본을 검사한다.

```bash
pnpm test
node scripts/audit-player-analysis.mjs --input tests/fixtures/player-analysis-real-cases.json --cohorts none --out .scheduler/player-analysis-offline-audit.json
```

최신 전적과 DB 비교군을 읽어 검증하려면 `.env.local`의 기존 공식 API·Supabase 설정을 사용한다. 이 도구들은 DB에 쓰거나 AI 호출을 하지 않는다. 원본은 Git에서 제외한 `.scheduler`에 저장한다. 비교군이 크면 수집에 시간이 걸릴 수 있다.

```bash
node scripts/fetch-player-analysis-audit.mjs --players 겜덕후,하스,음침해지기,세시아,사린 --cohorts .scheduler/player-analysis-cohorts.json
node scripts/audit-player-analysis.mjs --save-analyses .scheduler/player-analysis-replay.json
```

조회 한도에 도달했다면 출력의 `pageLimitReached`를 확인하고 `--max-pages`를 늘려야 한다. 현재 기록이 적은 계정을 오래된 기록으로 채우지는 않는다. 원본 캡처나 자격 증명을 커밋하지 않는다.
