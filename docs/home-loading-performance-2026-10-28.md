## 확인한 병목

- 운영 `https://project-erps.vercel.app/` GET 1회: HTTP 200, 첫 바이트 33.334301초, 전체 33.352884초, HTML 24,552바이트.
- 응답은 `Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate`, `X-Vercel-Cache: MISS`였다. `app/page.tsx`가 `force-dynamic`을 지정했다.
- 메인 페이지가 전체 조합 32,667개를 읽고 이름을 붙여 정렬한 뒤 5개만 표시했다. 공통 패치·최신 스냅샷·조합 count도 여러 경로에서 반복 조회했다.
- 공개 갱신 상태에는 집계 시각만 필요하지만 관리자용 상태 함수가 처리 대기열 count 3개, 벤치마크와 실행 로그까지 읽었다.
- 서버 응답 헤더의 실행 리전은 `iad1`이었다. Supabase의 실제 DB 리전은 확인하지 않았으므로 배포 리전은 변경하지 않았다. 리전 검토 시 사용자 위치만으로 선택하지 말고 DB와의 거리를 확인해야 한다. [Vercel 공식 리전 문서](https://vercel.com/docs/functions/configuring-functions/region).

## 변경

- 메인 페이지를 `revalidate = 60`으로 사전 렌더링하고, 캐시된 HTML을 재사용한다. [Next.js 설정 문서](https://nextjs.org/docs/app/api-reference/file-conventions/route-segment-config).
- DB 조회를 별도의 비동기 통계 컴포넌트로 옮겨 `Suspense`로 감쌌다. 캐시가 없는 렌더링에서도 티어표 바로가기와 닉네임 입력 화면은 통계를 기다리지 않는다.
- 공개 갱신 상태를 별도 조회 함수로 분리해 캐릭터·조합의 시각만 확인한다.
- 상위 조합은 게임 수 내림차순으로 500개씩 조회하며 상위 5개만 유지한다. 기존 점수는 `clamp01(performance) * log1p(games)`이므로 아직 읽지 않은 점수의 상한은 마지막으로 읽은 행의 `log1p(games)`이다. 현재 5위 점수가 이 상한보다 **클 때만** 멈춰 동점과 뒤쪽의 높은 승률 조합을 보존한다. 상대 티어의 분모는 전체 조합 count를 유지한다.
- 캐릭터·메타·패치·스냅샷 정보·count·상위 조합 읽기에 최대 60초의 프로세스 내부 캐시를 적용한다. 같은 진행 중 요청도 병합한다. 실패한 promise는 캐시하지 않으며 집계 종료 시 기존 `invalidateMetaReads()` 경로로 모두 비운다.
- 공통 `app/loading.tsx`로 이동 중 상태도 표시한다.

## 실제 데이터 조회 비교

읽기 전용으로 같은 Supabase를 조회했다. 아래 시간은 로컬 Node 프로세스에서 측정한 DB 읽기 시간이며 운영 사이트의 첫 바이트 시간과 직접 비교할 수 없다. 결과는 실행 순서·네트워크·DB 부하에 따라 변한다.

| 항목 | 전체 조합 읽기, 캐시 없음 | 개선된 상위 5개 읽기, 캐시 없음 | 개선된 상위 5개 읽기, 캐시 있음 |
| --- | ---: | ---: | ---: |
| 소요 시간 | 17,688ms | 3,097ms | 1ms 미만 |
| HTTP 요청 수 | 40 | 16 | 0 |
| DB 응답 본문 크기 | 14,247,535 bytes | 1,053,812 bytes | 0 |
| 읽은 조합 데이터 행 | 32,667 | 4,000 | 0 |

표시되는 조합 키·이름·순서·티어·게임 수·승률·TOP3·평균 순위·신뢰도가 기존 전체 읽기의 상위 5개와 일치했다. 저장소 내부 ID와 기간 등 표시하지 않는 컬럼은 새 쿼리에서 제외했다. HTTP 행 수 계측에는 최신 스냅샷 메타데이터 1행이 포함됐으며 표에서는 이를 제외했다.

재현:

```powershell
node --env-file=.env.local scripts/measure-home-performance.mjs
```

이 스크립트는 비밀값·응답 본문을 출력하지 않고, DB 조회만 수행한다. 현재 데이터에서 전체 읽기와 새 읽기의 표시 결과가 다르면 비정상 종료한다.
