# ERPS 기능 추가·변경 이력

최종 정리일: 2026-10-29 KST. 초기 MVP부터 현재 작업 파일까지, 저장소와 기존 검증 문서에서 확인되는 기능 추가·개선·정책 변경·운영 및 문서 변경을 모았다.

| 문서 | 기록 대상 |

| [문제·버그 기록](issue-log.md) | 의도한 동작을 벗어난 증상, 재현 조건, 원인, 수정 과정, 검증과 재발 방지 |

새 필터를 추가하면 기능 변경, 기존 필터가 상세에서 사라지는 문제를 고치면 버그 기록에 남긴다. 한 작업에 둘 다 있으면 이 문서에 변경을 요약하고 관련 `ERPS-번호`로 연결한다. 상세 원인·재현 과정은 버그 문서에서 관리한다.

- 항목 ID는 `CHG-001`부터 순서대로 부여하고 재사용하지 않는다. 아래 번호는 이번에 과거 이력을 정리하며 부여한 식별자다.
- 날짜는 KST의 **프로젝트 수정 커밋일 또는 검증 기록일**이다. 게임 패치 출시일·첫 수집일·서비스 배포일과 구분한다. 여러 날의 변경은 범위를 표시한다.
- 날짜별 목록과 상세 이력은 **오래된 날짜 → 최신 날짜** 순서로 맞춘다. 기간은 시작일, 같은 날짜는 ID 오름차순을 기준으로 한다. 과거 변경을 나중에 등록해도 해당 날짜 위치에 삽입하며 기존 ID·앵커는 유지한다. 날짜 미확인 항목은 마지막에 둔다.
- 과거 커밋·문서의 내용은 당시 상태로 보존한다. 예전 30경기·6개 영역·캐시 버전 16/19 등의 정책을 현재 정책으로 해석하지 않는다. 현재 소스의 분석 상한은 50경기, 분석 캐시 버전은 20이다.
- 아래 과거 항목의 공통 상태는 **구현 이력 확인, 운영 반영 미확인**이다. 커밋·테스트 파일의 존재만으로 당시 테스트 통과나 실제 배포를 추정하지 않는다. 실행 결과가 남은 항목은 따로 적었다.
- 10-28 메인 성능 개선은 **GitHub `Test` → `main` 반영·운영 배포·메인 응답 확인 완료**다. 최초 문서 정리 이후의 반영·검증 이력은 CHG-016에서 관리한다.
- 문서별 상세 증거와 수정 커밋을 연결했다. 제안만 있는 기능을 구현 완료로 넣지 않았다.

## 상세 이력

<a id="chg-001"></a>

### CHG-001 — 2026-06-12 초기 MVP

- **구분·이유:** 신규 기능. 게임 메타·조합·추천을 하나의 웹 서비스에서 조회할 기본 구조를 마련했다.
- **화면:** 메인, 캐릭터 티어·상세, 추천, 플레이어 요약, 패치노트 관리자 화면을 추가했다.
- **데이터·API:** Supabase 경기·참가자·메타·조합·패치·수집 이력과 `player_summary` RPC, 공식 API 수집·스냅샷 생성, 메타·조합·요약·추천·패치 import API를 추가했다. OpenAI Responses API를 사용하는 한국어 추천 설명 경로도 포함됐다.
- **당시 운영 구성:** 12시간 간격 Vercel Cron 설정이 소스에 들어 있었다. 실제 스케줄 성공을 검증한 기록으로 해석하지 않는다. 이후 [CHG-003](#chg-003)에서 이 설정을 제거했다.
- **검증·상태:** 통계·파서 테스트가 추가된 커밋을 확인했다. 당시 실행 결과·배포 상태는 별도 미확인이다.
- **근거:** [초기 MVP 커밋 db09e90](https://github.com/Hy0yH/Project_ERPS/commit/db09e90e90b420a6c80a74ed14b10d71481467b2), [001 DB 스키마](../supabase/migrations/001_initial_schema.sql).

### CHG-002 — 2026-08-19 랭크·무기 메타와 개인 분석 확장

- **구분·이유:** 기능 추가·UI 개선. 전체 메타뿐 아니라 랭크·무기·개인 전적을 반영하는 조회와 추천으로 확장했다.
- **메타·조합:** 실험체·무기별 스냅샷, 전체/단일 티어/특정 티어 이상 랭크 범위, 완성된 스쿼드의 2인·3인 조합 통계를 도입했다. 기본 메타 범위는 미스릴 이상이다.
- **개인 추천:** 닉네임과 시즌/현재 패치 범위, 직접 선택한 팀원을 반영하고 개인 실험체 사용 기록을 저장하는 프로필 구조를 추가했다.
- **당시 플레이 분석:** 최근 30경기와 유사 MMR·같은 실험체/무기를 비교하고, 6개 영역·표본 신뢰도·캐시·한계를 표시했다. 500 MMR 구간과 인접 구간 보완, 선택적인 AI 요약을 포함했다. 현재의 50경기·5개 평가 영역과 별도 지원 활동 정책은 [CHG-012](#chg-012)의 변경이다.
- **수집·운영:** 랭커별 커서, 재시도 가능한 경기 큐, 외부 UID 저장, 개인 상세 지표·벤치마크·분석 캐시와 Windows 예약 수집 스크립트를 추가했다. 화면·메뉴·추천 폼·반응형 스타일도 확장했다.
- **데이터 기준:** 최초 수집 기준 패치 12.1.0이 설정에 기록됐다. 이것을 6월 MVP 작성일부터 12.1 데이터를 수집했다는 뜻으로 해석하지 않는다.
- **검증·상태:** 역할별 테스트와 DB 마이그레이션 002~007이 추가된 이력을 확인했다. 당시 배포·실행 결과는 별도 미확인이다.
- **근거:** [확장 커밋 884390d](https://github.com/Hy0yH/Project_ERPS/commit/884390d068ec1462e359a8621d2361221dd4726d), [당시 README](https://github.com/Hy0yH/Project_ERPS/blob/884390d068ec1462e359a8621d2361221dd4726d/README.md).

- **운영 반영:** 문서에 한해 적용 불필요. 앱 코드 배포·DB 변경·재수집·기존 행 정리 없음.

### CHG-022 — 2026-10-29 수집 데이터 정확성과 실패 복구 보완

- **구분·변경 이유:** 기능·운영 변경 및 버그 수정. CHG-021에서 재현한 중복 참가자·잘못된 경기 완료·재시도 소진·실행 상태 오판정과 기존 집계 중간 결과 노출을 보완하고 GitHub에 올리라는 요청에 따른 작업이다.
- **추가·변경 내용:** 개인/정기 수집의 UID 키 통일, 경기·참가자·완료 표시의 DB 트랜잭션 저장, 개인 부분 전적과 전체 상세의 분리, 완료 경기만 집계하는 입력 검증을 구현했다. 일시 오류의 지연 재시도·영구 오류 상태와 인증된 선택 재개 UI/API, 30초 heartbeat·10분 DB lease·만료 실행/큐 선점 회수, 정상/부분 실패/전체 실패 상태와 오류 코드 기록을 추가했다. 집계 결과를 배치로 임시 저장한 뒤 세 테이블을 한 번에 공개하며 실패 시 기존 결과를 유지한다.
- **사용자에게 달라지는 점:** 개인 분석과 정기 수집이 같은 참가자를 중복 저장하거나 일부 개인 기록만으로 경기 전체 수집을 건너뛰는 조건을 막는다. 운영자는 실패 종류·최근 응답·중단 상태와 선택 재개를 확인할 수 있다. 신규 경기 0건인 정상 실행과 전체 수집 장애를 구분한다.
- **사용 조건·영향:** 새 [마이그레이션](../supabase/migrations/20261029121254_collection_reliability.sql)을 009 이후 적용해야 한다. 기존 writer 중단→마이그레이션→새 코드→수집→집계 순서다. 과거 완료 상태를 인원수로 추정하지 않아 현재 패치 경기는 실행 한도 내에서 다시 상세 검증한다. 이전 패치 자료를 일괄 삭제하거나 과거 전체 중복을 자동 정리하지 않는다. [적용·복구 절차](collection-reliability-2026-10-29.md)를 따른다.
- **구현 상태:** 코드·마이그레이션·관리 UI/API·회귀 검사 구현 완료. 실제 Supabase의 새 RPC, 운영 데이터 재검증과 대규모 집계 성능은 미검증이다.
- **검증 결과:** Windows에서 전체 43파일·294테스트와 타입 검사 통과. PGlite 0.5.13의 Postgres 엔진으로 001~009와 새 SQL을 순서대로 적용하고 저장/집계 오류 롤백·권한/RLS·lease·중단 큐 회수·기존 행 보존을 검증했다. 별도 `.next-qa` 프로덕션 빌드 성공. 운영 `.next`·환경 변수·예약 작업과 운영 DB 쓰기는 변경하지 않았다. [검증 증거](evidence/collection-reliability-validation-2026-10-29.json).
- **운영 반영:** 미배포·운영 DB 미적용. GitHub 업로드는 운영 적용과 별도로 관리한다. 과거 대규모 집계 장애를 해결 완료로 판정하지 않는다.
- **관련 버그:** [ERPS-032](issue-log.md#erps-032)~[ERPS-036](issue-log.md#erps-036), [ERPS-006 / QA-005](issue-log.md#erps-006). 상세 원인·재현·후속 상태는 문제 기록에 유지한다. 공유 API 키 한도 QA-010과 영구 배치 계산 재개는 후속 범위다.

아래 항목은 과거 제안·후속 계획이며 위 완료 기능과 구분한다.

- **영상·리플레이·실제 이동/교전 분석(F-12):** 원본 입력이 필요해 보류. 시작 루트 ID나 종료 장비 표시와 다르다.
- **영구 분석 작업·워커:** 서버 재시작이나 다른 인스턴스에서 분석을 이어받는 공유 큐·작업 저장소는 미구현이다.
- **계정 기반 이력·기기 간 동기화:** 현재 수동 브라우저 저장과 다르다.
- **고정 결과 공개 공유:** 현재 조회 링크는 최신 결과를 불러오며 당시 분석을 고정 공개하지 않는다.
- **자유로운 LLM 후속 대화:** 현재 근거 질문은 규칙 기반이며 기존 AI 요약 기능과 별도다.
- **집계의 영구 체크포인트 재개·인스턴스 전체 API 할당량:** 후속 범위다. 원자적 공개와 수집/집계 DB lease는 [CHG-022](#chg-022)에서 로컬 구현·검증했으나 운영 반영과 대규모 성능 검증은 남는다. [ERPS-006](issue-log.md#erps-006)과 [QA 백로그](qa-backlog.md)에서 후속 조건을 관리한다.
- **임의 기간·일별 추세·행동 수행 효과 추적:** 현재 패치/보관 패치 비교와 최근 기록 비교 범위를 넘어서는 기능은 후속 검토다.
