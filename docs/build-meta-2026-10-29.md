# 아이템·특성·루트 상세 메타

기준일: 2026-10-29 KST. 기능 이력: [CHG-020](change-log.md#chg-020).

## 구현 범위

- 경기 원본의 종료 5부위 장비, 핵심·주 보조·부 보조 특성, 전술 스킬 종류/레벨, 스킬 습득 순서, 시작 루트 ID/슬롯과 시작 지역을 `equipment.__analysis.details`에 저장한다. 새 상세 수집 버전은 `build_data_version=2`다.
- 랭커 수집 시 공식 `/v2/data/hash`에서 제공 여부를 확인해 `ItemWeapon`, `ItemArmor`, `Trait`, `TacticalSkill`/`TacticalSkillGroup` 카탈로그를 수집한다. 코드·한국어 이름·원본 능력치·해시·조회 시각을 패치별로 보관한다. 필수 아이템 테이블이 없거나 응답이 실패하면 해당 갱신 실패를 알리고 경기 수집은 계속한다. 제공되지 않는 특성/전술 테이블은 결과의 `missing`에 표시한다.
- 전체 카탈로그 배치가 저장된 뒤에만 완료 해시를 공개한다. 부분 실패를 완료로 오인해 다음 실행에서 건너뛰지 않는다. 카탈로그 원본은 조회 당시 API 값이며, 나중에 과거 능력치를 복원한 자료로 해석하지 않는다.
- 기존 현재 패치의 상세 버전이 낮은 경기는 실행당 최대 1,000개, 기존 수집 한도 안에서 큐에 보충한다. 완료된 항목만 재개방하고 처리 중 항목·실패 재시도 횟수·다른 패치 자료는 보존한다. 같은 게임을 재수집할 때 참가자 기본 키로 갱신한다.
- 스냅샷은 기존의 정확한 시즌/패치·랭크·실험체/무기 검사를 통과한 참가자만 사용한다. 상세 통계는 동일한 `character_stats_snapshot` 행의 `build_stats`에 저장된다.
- 관측된 시작 루트의 공유 설정은 스냅샷 작업에서 많이 사용된 순서로 추가 조회한다. 1회 기본 한도는 20개, `ER_ROUTE_FETCH_LIMIT=0`이면 생략한다. 조회 시작 후 30초가 지나면 다음 요청부터 보류한다(이미 진행 중인 요청의 제한/재시도는 기존 API 정책 적용). 24시간 캐시를 사용하며 삭제/비공개 응답도 캐시해 다음 루트의 수집이 진행되게 한다. API 실패는 경기/통계를 지우지 않고 실패 수로 반환한다.

## 통계 정의

집계 단위는 **참가자-경기**다. 같은 경기/참가자를 중복 계산하지 않는다.

| 통계 | 유효 경기·사용률 분모 |
| --- | --- |
| 개별 종료 아이템 | 그 장비 부위에 유효 아이템 코드가 확인된 경기 |
| 종료 장비 조합 | 5부위가 모두 확인된 경기 |
| 개별 특성 | 핵심/주 보조/부 보조/과거 분류 미수집 중 같은 분류가 확인된 경기 |
| 전체 특성 조합 | 핵심 1개와 주/부 보조 각 2개가 중복 없이 확인된 경기 |
| 시작 루트·전술 스킬·스킬 순서·시작 지역 | 각 정보가 확인된 경기 |

각 구성은 사용 경기 수, 분모, 승리 수·TOP3 수, 사용률, 승률, TOP3 비율, 평균 순위와 표본 상태를 갖는다. 승률·TOP3·평균 순위는 **그 구성을 사용한 경기**만 분모로 쓴다. 보조 특성은 한 경기에 여러 개를 선택하므로 합계 사용률이 100%를 넘을 수 있다.

구성이 미수집인 경기는 전체 경기 수에는 포함하되 해당 항목의 분모에서 제외한다. 오래된 특성 배열은 분류를 추측하지 않고 별도 분류로 보존한다. `coverage`는 항목별 유효 경기 수, `variant_counts`는 관측된 전체 구성 수다. 저장/API 목록은 사용 경기 수 순으로 아이템 상위 50개, 다른 항목 상위 20개이며 화면은 각 상위 10개를 표시한다. 전체 경기 원본은 계속 보관한다.

종료 장비는 생존·성장과 획득 시점의 선택 편향을 포함한다. 장비의 관측 승률을 해당 장비를 선택하면 얻는 승률로 설명하지 않는다. 공유 루트의 원본에는 후반 장비·특성·전술 스킬·버전도 보관하지만, 화면은 제목·예정 지역·목표 장비와 조회 시각을 요약한다. 경기 당시 루트 구성이나 실제 이동 경로로 단정하지 않는다.

## 패치·추천 연결

- 아이템/무기/방어구, 특성, 전술 스킬의 일반 모드 변경을 별도 파싱한다. 코발트·론울프 섹션은 제외한다. 원문·수치·패치 버전·대상 종류/이름과 코드를 보관한다. 공식 카탈로그에서 같은 종류·이름의 코드가 유일할 때만 자동 연결한다.
- 자동 추출은 미검수 상태다. `/admin/patch-notes`에서 원문과 공식 대상 코드를 확인하고 검수를 완료해야 근거로 사용한다. 관리자 `PATCH /api/admin/patch-notes/import`는 인증과 해당 패치 카탈로그를 검사한다. 재import는 기존 검수를 지우지 않는다.
- 현재 12.7의 일반 모드 장비/전술 변경인 진실의 칼날, 이단심판관, 서슬가시 체인은 [공식 원문](https://playeternalreturn.com/posts/news/3924?hl=ko-KR)과 저장소의 기존 원문 확인 자료에 근거해 검수된 기본 데이터로 포함했다. 해당 특성 변경이 없는 패치에 특성 변경을 만들어 넣지 않는다.
- 실제 사용된 코드/확인된 이름과 일치하는 **현재 패치의 검수된 변경**만 연결한다. 실험체 추천의 기존 규칙 점수에 장비 변경을 임의로 가산하지 않는다.
- 추천 설명에는 해당 픽의 자주 관측된 핵심 특성과 종료 장비 및 관련 공식 변경을 추가한다. AI 코칭에는 개인 사용 기록, 같은 패치의 픽별 메타(최대 3픽), 유효 표본·기간·랭크 범위, 항목별 상위 3개와 검수된 변경을 제공한다. 기존 강점/점검 제안과 확정 수치를 바꾸지 못하게 유지한다.
- 분석 캐시 버전은 21이다. 상세 메타는 전용 조회에서만 읽고 메인 티어 통계의 응답에 큰 상세 JSON을 포함하지 않는다.

## 적용·운영 절차

1. 기존 001~008이 적용된 DB에 [009_build_meta.sql](../supabase/migrations/009_build_meta.sql)을 적용한다. 새 테이블은 RLS를 활성화하고 서버의 서비스 역할로만 접근한다.
2. 수집 환경의 `ETERNAL_RETURN_API_KEY`, `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, 시즌·관리/수집 인증 설정을 준비하고 새 코드를 배포하거나 수집 서버 빌드를 갱신한다.
3. 기존 예약 수집 또는 인증된 `POST /api/cron/collect-rankers`로 카탈로그·경기·누락 상세를 수집한다. 결과의 `buildCatalog`, `detailBackfill`과 재시도 큐 상태를 확인한다.
4. 인증된 `POST /api/cron/build-snapshots`로 상세 통계를 생성하고 루트 정의의 `saved/unavailable/failed/deferred`를 확인한다. 기존 Windows 수집 스크립트는 이 두 작업을 순서대로 실행한다.
5. `/characters/[code]?weapon=...&rankScope=...` 또는 `GET /api/characters/[characterCode]/builds?weapon=...&rankScope=...`에서 범위·집계 시각·항목별 수집률을 확인한다. 현재 패치 집계가 없으면 `data:null`/집계 대기로 표시한다.
